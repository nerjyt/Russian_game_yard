# «Двор» — играбельный прототип

Социальная дедукция во дворе 2000-х. Работающий вертикальный срез на **Unity 6 + Netcode for GameObjects**:
карта, роли, Скука, дела, вещдоки, участковый с протоколами, стукачи, сходка с голосованием,
условия победы и **голосовой чат по дистанции без внешних SDK**.

## Запуск: три шага

1. **Unity Hub → Open → выбрать папку `Dvor`.** Нужна Unity 6 (6000.x). Unity сам подтянет
   Netcode for GameObjects из `Packages/manifest.json` — первый импорт займёт пару минут.
2. **Меню `Двор → Собрать проект`.** Скрипт соберёт префаб игрока и сцену. Делает это сам Unity,
   поэтому все GUID получаются правильными.
3. **Play → «Создать двор (хост)».**

Если Unity попросит перезапуск из-за Active Input Handling — перезапусти и повтори шаг 2.

### Как сыграть вдвоём

`File → Build Settings → Build`, запусти билд, в нём «Зайти» с IP `127.0.0.1`. Редактор при этом хостит.
По локальной сети — тот же билд, но IP хоста вместо `127.0.0.1`. Порт 7777 UDP.

Минимум для старта партии стоит **2** игрока (для отладки). Для настоящей игры поставь
`MinPlayers = 6` в `Balance.cs` — на двоих расклад ролей вырожденный.

## Управление

| Клавиша | Что делает |
| --- | --- |
| WASD, Shift | Ходьба, бег |
| Мышь | Обзор |
| **E** (держать) | Сделать своё дело — подойти к нужной точке, она подсвечена жёлтым кругом |
| **Q** | Поднять улику · подбросить · у помойки выкинуть |
| **M** | Созвать сходку (у беседки, один раз за партию) |
| **ESC** | Освободить курсор |
| **F** (держать) | Участковый: протокол. Нужно смотреть на нарушителя и не двигаться |
| **G** / **H** | Участковый: проверка документов / профбеседа |
| **R** | Участковый: вызвать наряд из опорного пункта |

Микрофон включается сам. Тебя слышно в радиусе 22 метров, хорошо — до 6.
На сходке слышно всех. В УАЗике — только других задержанных.

## Что реализовано

- **Фазы** Утро → День → Сходка → Вечер, четыре дня, сетевой таймер
- **Роли**: гопник, алкаш, спортик, барыга, бабка с первого, форточник + участковый
- **Скука** 0–100, растёт сама, сбрасывается делами; при проверке документов растёт вдвое
- **Дела** с проверкой дистанции, фазы, роли и напарника **на сервере**
- **Вещдоки**: остаются после дел, их можно поднять, подбросить в чужой подъезд или выкинуть
- **Свидетели**: сервер отмечает, кто видел преступление — из этого растут доносы
- **Стукачи**: настоящая роль-прикрытие, секретное дело у таксофона или почтового ящика
- **Участковый**: протокол, проверка документов, профбеседа, вызов наряда с трёх протоколов
- **Сходка**: созыв у беседки, тайное голосование, 15 суток. Роль выгнанного не раскрывается
- **Победа** обеих сторон, включая проигрыш двора за два ошибочных изгнания подряд
- **Голос по дистанции**: отсечка по дальности делается на сервере, а не на клиенте

## Чего нет и почему

Анимаций, моделей, звука, лобби через интернет, античита, прогрессии. Всё это стоит делать
после того, как на серых кубах окажется весело. Если на плейтесте люди не спорят и не смеются —
проблема в дизайне, и ассеты её не починят.

## Где что лежит

```
Assets/_Dvor/
  Scripts/
    Core/     Balance (все числа), GameStateMachine (фазы и итоги), MapBuilder, RoleCatalog
    Player/   PlayerState, PlayerMotor, PlayerInteractor
    Cop/      ProtocolBook
    Meeting/  MeetingManager
    Voice/    ProximityVoice
    UI/       HudUI (весь интерфейс на IMGUI)
  Editor/     DvorSetup — сборка префаба и сцены
```

**Баланс правится только в `Balance.cs`.** После тридцати партий половина этих чисел станет другой.

**Карта строится кодом** в `MapBuilder.cs` — планировка та же, что в дизайн-доке: гаражи на западе,
двор между двумя пятиэтажками, ларёк у торца, беседка и площадка ломают обзор, пустырь как зона риска.
Двигать точки дел проще там, чем мышкой в сцене.

## Принцип, который нельзя нарушать

**Сервер знает всё, клиент — только своё.** Роль, стукачество, Скука и протоколы лежат в
`NetworkVariable` с правами `Owner`; список свидетелей и автор улики вообще не сериализуются.
Клиент ничего не применяет сам — он просит, сервер перепроверяет дистанцию, фазу и роль.
Каждое отступление от этого правила — готовый чит, который вскроет роли через неделю после релиза.

## Первые шаги после запуска

1. Сыграть вдвоём, проверить, что дела, протоколы и голосование работают.
2. Поднять `MinPlayers` до 6 и собрать компанию — раньше этого о балансе судить нельзя.
3. Логировать партии: кто выиграл, сколько дней, сколько было срывов. Тридцать партий — и станет
   видно, куда крутить числа.
4. Голос заменить на Vivox, когда дойдёт до релиза: там эхоподавление и модерация из коробки.
